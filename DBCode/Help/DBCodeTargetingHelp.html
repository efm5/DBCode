Targeting

The whole concept of DBCode is to move text from one Dragon-friendly text editor (DBCode) into another text editor (the primary focus is on IDEs, but it works just as well anywhere text can be pasted). Where the pasted code lands depends on whether DBCode is “targeted” or “untargeted”.

The DBCode Targeting Concept

DBCode’s Targeting menu

“Targeted” (Ctrl+d) on the Targeting menu is a toggle— when checked it is on; otherwise targeting is untargeted. “Retarget” (Ctrl+e) allows the user to change the target.

When “Targeted” is not checked and the user selects “Targeted”, it becomes checked and DBCode enters the targeting behavior. The first thing that happens is a Target Picker dialog opens:

DBCode’s Target Picker

If the user chooses to “Cancel” “Targeted” is unchecked and targeting is turned off. If the user chooses one of the potential targets, it will become the “target” until targeting is turned off or “Retarget” is used to choose a different target.

Targeted Transfer

Targeted transfer forces the targeted application to the top of the Z–Order. Whatever text is being transferred is pasted into the target application at its current cursor location.

Untargeted Transfer

Untargeted transfer forces the next application in the Z–Order (below DBCode) to the top so that whatever text is being transferred is pasted into the top application at its current cursor location.

Retarget

If the user chooses “Retarget” the Target Picker opens. If the user chooses “Cancel” the existing target remains in effect. Otherwise, a new target is established.

The Line–Endings Items

These three items () have no direct effect on targeting but do affect how the text ends up formatted the target. See: line–endings for more details.
